# Пульс бизнеса

Публичный веб-дашборд для портфельной компании. Он читает бизнес-метрики из CSV, показывает динамику по ключевым показателям, подсвечивает проблемные зоны и помогает быстро сделать первый управленческий вывод по данным.

Дашборд отвечает на три вопроса:

- бизнес растет или замедляется;
- где ухудшается качество роста;
- что проверить в первую очередь по выбранному периоду.

## Что умеет дашборд

- загружает данные из реального Google Sheets CSV, а не из захардкоженного массива;
- пересчитывает KPI, графики и сигналы риска для `3M`, `6M`, `12M`;
- поддерживает режимы сравнения:
  - `Без сравнения`
  - `К предыдущему периоду`
  - `Первая vs вторая половина`
- показывает 4+ смысловых блока:
  - KPI-карточки;
  - основной график `Выручка + Новые клиенты`;
  - блок `Что требует внимания`;
  - вторичные метрики `LTV/CAC`, `Маржа`, `Приток клиентов`, `Отток`;
  - таблицу исходных данных;
- генерирует AI-инсайт через реальный server-side вызов `OpenRouter`;
- позволяет загрузить новый набор данных из файла;
- локально сохраняет загруженные наборы в браузере;
- умеет сравнивать текущую и предыдущую таблицу через отдельный AI-сценарий.

## Локальный запуск

1. Установить зависимости:

```bash
npm install
```

2. Создать `.env.local` в корне проекта:

```env
OPENROUTER_API_KEY=your_openrouter_key
OPENROUTER_MODEL=openrouter/auto
CSV_SOURCE_URL=https://docs.google.com/spreadsheets/d/1CiXEJboFXmUznr3xuBpzuk8_sgWBVqZExHeGfguQO64/export?format=csv&gid=0
```

3. Запустить dev-сервер:

```bash
npm run dev
```

4. Открыть локальный адрес из вывода Vite.

## Переменные окружения

- `OPENROUTER_API_KEY` - обязательный ключ для server-side вызова OpenRouter
- `OPENROUTER_MODEL` - имя модели OpenRouter
- `CSV_SOURCE_URL` - server-side URL базового CSV-источника
- `VITE_CSV_SOURCE_URL` - опциональный клиентский fallback для CSV URL

API-ключ хранится только на серверной стороне. Во frontend bundle он не попадает.

## Как устроены данные

### 1. Базовый источник

Базовый набор данных загружается через `fetch()` из Google Sheets CSV в `src/lib/dashboard/csv.ts`.

Что делает слой CSV:

- загружает реальный CSV по URL;
- проверяет обязательные колонки;
- парсит русские месяцы;
- нормализует валюты, проценты и числа;
- сортирует строки по порядку месяцев;
- возвращает нормализованные записи для бизнес-логики.

Обязательные поля:

- `Месяц`
- `Выручка`
- `Новые клиенты`
- `LTV`
- `Отток`
- `Маржа`
- `CAC`

### 2. Пользовательские наборы данных

Через `Dataset Manager` владелец может загрузить новую таблицу:

- `CSV`
- `XLS`
- `XLSX`
- `TSV`
- `ODS`

Загруженные наборы:

- нормализуются тем же слоем `normalize.ts`;
- сохраняются локально в браузере;
- не требуют отдельной серверной БД;
- не синхронизируются между устройствами;
- могут использоваться как активный источник для дашборда;
- могут использоваться как база для AI-сравнения таблиц.

### 3. Где хранится история наборов

Для этой версии история хранится локально в браузере через `localStorage`.

Почему так:

- это самый простой путь для тестового;
- данные не уходят в сторонний frontend API;
- не нужно поднимать отдельную серверную БД;
- наборы не теряются после обычного перезапуска страницы на этом же устройстве.

Ограничение:

- данные не шарятся между устройствами и браузерами.

## Как считаются метрики

Расчеты находятся в `src/lib/dashboard/metrics.ts`.

Считаются:

- значения за выбранный период;
- значения последнего месяца;
- сравнение с предыдущим периодом;
- `month-over-month` динамика;
- сравнение `первая половина года vs вторая половина года`;
- `LTV/CAC`;
- risk-флаги и сигналы для блока `Что требует внимания`;
- `health score`;
- snapshot, который используется и UI, и AI-слоем.

## AI Insight: OpenRouter

В проекте используется `OpenRouter` как API-провайдер.

Важно:

- frontend не знает `OPENROUTER_API_KEY`;
- ключ читается только на серверной стороне;
- инсайт строится через реальный server-side вызов, а не через mock;
- основной AI-инсайт находится в `src/lib/dashboard/insight.ts`;
- AI-сравнение таблиц находится в `src/lib/dashboard/dataset-comparison-insight.ts`.

### Что отправляется в модель для основного инсайта

В модель отправляется не сырой CSV, а подготовленный payload:

- выбранные месяцы;
- значения по строкам периода:
  - `revenue`
  - `newCustomers`
  - `ltv`
  - `churnRate`
  - `margin`
  - `cac`
  - `ltvCacRatio`
- дельты относительно базы сравнения;
- risk-сигналы из блока `Что требует внимания`;
- labels текущего и базового периода.

### Что отправляется в модель для сравнения таблиц

Для AI-сравнения двух наборов в модель отправляется:

- имя текущего набора;
- имя предыдущего набора;
- label периода;
- `health score` двух наборов;
- подготовленные агрегаты по ключевым метрикам;
- top risk-сигналы текущего и предыдущего набора.

Это позволяет модели сравнивать уже нормализованные бизнес-данные, а не пытаться разбирать сырой файл.

## Системный prompt

### Основной AI-инсайт

```text
Ты аналитик портфельной компании.
Используй только переданные цифры и не придумывай факты или причины, которых нет в данных.
Если уверенного вывода нет, скажи об этом прямо.
Пиши кратко, на русском языке и в тоне для руководителя.
Верни ровно пять строк с такими префиксами:
Что изменилось:
Что настораживает:
Что проверить первым:
Короткий вывод:
Ограничение:
```

### AI-сравнение таблиц

```text
Ты аналитик портфельной компании.
Сравни две версии бизнес-таблицы и используй только переданные цифры.
Не придумывай причины, которых нет в данных.
Пиши кратко, на русском языке, в тоне для руководителя.
Верни ровно пять строк с такими префиксами:
Что улучшилось:
Что ухудшилось:
Что проверить первым:
Короткий вывод:
Ограничение:
```

## Почему prompt устроен именно так

Prompt ограничивает модель по нескольким направлениям:

- модель не получает свободу фантазировать про причины, которых нет в данных;
- у нее есть строгий формат ответа;
- она обязана ссылаться на подготовленные цифры;
- она должна явно обозначать ограничение или недостаточность данных.

Это снижает hallucinations и делает ответ похожим на короткий управленческий summary, а не на общее AI-эссе.

## Что происходит, если данных или ответа модели недостаточно

В `src/lib/dashboard/insight.ts` и `src/lib/dashboard/dataset-comparison-insight.ts` есть fallback:

- если `OPENROUTER_API_KEY` не задан, сервер вернет ошибку;
- если OpenRouter вернул пустой или плохо разбираемый ответ, UI показывает rule-based или fallback comparison summary;
- предварительный rule-based инсайт визуально отделен от финального ответа модели.

## Проверка перед сдачей

Минимальный чек-лист:

- данные реально приходят из CSV;
- период `3M / 6M / 12M` меняет KPI, графики и таблицу;
- режим сравнения меняет deltas и attention signals;
- кнопка AI-инсайта делает реальный server-side запрос;
- менеджер наборов открывается и позволяет загрузить новый файл;
- загруженный набор можно сделать активным источником;
- AI-сравнение таблиц работает через отдельный server-side вызов;
- ключ не попадает в frontend bundle;
- `npm run build` проходит.

## Deploy на Vercel

Проект подготовлен под `Vercel` через `Nitro` preset `vercel`.

### Вариант 1. Через GitHub import

1. Залить код в GitHub.
2. В Vercel создать `New Project`.
3. Импортировать репозиторий.
4. Framework preset можно оставить `Other`.
5. Build Command:

```bash
npm run build
```

6. Install Command:

```bash
npm install
```

7. Добавить env-переменные в Vercel:
   - `OPENROUTER_API_KEY`
   - `OPENROUTER_MODEL`
   - `CSV_SOURCE_URL`

8. Запустить deploy.

### Вариант 2. Через Vercel CLI

```bash
npm install -g vercel
vercel
```

При первом запуске:

- выбрать текущую папку;
- подтвердить link/create project;
- добавить env-переменные в Vercel dashboard или через CLI;
- задеплоить проект.

### Что проверить после deploy

- страница открывается публично без логина;
- базовый CSV грузится;
- периоды работают;
- AI-инсайт генерируется;
- ключ не виден во frontend;
- загрузка локального набора работает.

Важно: локально загруженные наборы хранятся в браузере пользователя. На проде они тоже будут храниться локально в браузере и не синхронизируются между устройствами.

## Продуктовые решения

- Выручка и новые клиенты вынесены в основной график, чтобы сразу показать масштаб и фазу роста.
- `LTV/CAC`, `Маржа`, `Отток` вынесены в отдельные блоки, чтобы быстро видеть качество роста.
- `Что требует внимания` работает как короткий risk-priority список для менеджмента.
- AI-инсайт получает уже подготовленные метрики и сравнения, а не сырой файл.
- Владелец может загрузить новый набор данных без изменения кода и сразу использовать его в дашборде.

## Ограничения текущей версии

- пользовательские наборы хранятся локально, а не в общей серверной БД;
- данные не синхронизируются между устройствами;
- parser ожидает определенный набор колонок;
- `xlsx` вынесен в lazy chunk, но сам файл-парсер остается тяжелой зависимостью;
- часть `Recharts` dev-warnings может сохраняться в dev-режиме, хотя production build проходит корректно.

## Что можно улучшить в следующей версии

- перевести локальную библиотеку наборов на настоящую серверную БД;
- добавить импорт по URL, а не только через файл;
- сделать mapping колонок для произвольных названий полей;
- добавить AI-чат по данным с follow-up вопросами;
- расширить anomaly detection;
- экспортировать AI-инсайт в PDF или email summary;
- сохранить историю сравнений и инсайтов для команды;
- добавить auth, если инструмент станет внутренним продуктом.
